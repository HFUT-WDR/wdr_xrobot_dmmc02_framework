# 底盘功率控制接入

> 后续控制组织与功率行为已更新，以[对齐记录](control_alignment_20261106.md)为准；本文保留此前验证与设计背景。

## 已确认的契约

车体参数和超电协议沿用26_sentry，算法参考本地RM2024-PowerModule；超电离线回退裁判缓冲，两路都失效时保守降额，无可信实测功率时暂停RLS。本轮仅编译与离线验证，不烧录，不运行电机。

## 实现与调用

`Chassis::FeedbackUpdate()`在周期入口读取一份裁判功率快照、超电帧和电机反馈，随后整拍共用。`ControlLoop()`完成轮速PID，`PowerUpdate()`调用`PowerControl::Calculate()`和`Control::ApplyPower()`，再由原`SendOutput()`复查当前失控/STOP并发送。底盘仍为2ms单任务，没有功率线程、ISR融合或ISR Topic发布。

`PowerControl`与`SuperCap`随Chassis组件发布；前者无设备、无线程，后者只适配超电CAN，由底盘任务调用。公共PID增加`TrackIntegral()`，只有外部限幅实际改变输出时才反算积分；普通PID路径保持原行为。RMMotor增加只读逻辑方向反馈电流接口，不改原torque字段含义。

## 数据源与离线分支

- 超电正常且新鲜：使用百分比能量及Pout实测功率。默认正常状态码0，可由`cap_param.normal_state`调整；尚待实际超电固件确认。100ms超时。
- 超电失效且裁判0x0201、0x0202均新鲜：使用裁判功率上限和缓冲能量，RLS冻结。500ms超时。
- 两路能量反馈都不可用：能量环清历史，预算为有效裁判上限或配置的100W哨兵基准×0.85。100W来自原车，不是当前赛事规则声明。
- 裁判功率上限与缓冲能量分别记录合法报文完成时刻，其他消息不能替它们续期。超电数据和接收时间一起复制；无新帧不改时间。
- 当前裁判0x0202的旧实时功率字段已为保留位，绝不拿它训练RLS。只用新鲜超电样本，每个时间戳最多学习一次；停机、错误状态、过期及低于15W时不学习。

## 参数和必要差异

保留模型`P=τω+k1|ω|+k2τ²+k3`、电机协议电流到扭矩系数1.90484e-5、初值0.01470/476.3/3.77、协方差0.1、遗忘因子0.99999和原车k1/k2范围。能量阈值超电40/20百分比、裁判60/50J，PD为原每拍20/0.05、输出100W、最低预算30W。原车输入目标0.85/0.95过渡、0.3系数及减5W偏置保留。

按RM2024的误差/功率混合权重逐轮分配，二次方程反解电流。离线测试发现直接分配总预算会给部分轮低于其自身损耗的目标，导致合计仍超预算，因此先预留各轮允许电流区间内最小模型损耗，再分配剩余预算。不反向、不放大原请求；负功轮不为其他轮增加预算。若最低模型损耗仍超预算，标记`budget_unreachable`；这时不能声称已经达到功率上限。

切换能量来源或失控清能量微分历史，保留已辨识模型；不恢复陈旧运动目标。最终失控保护仍发送零电流，功率状态中的limited_current仅代表功率阶段提案，最终输出以State.current为准。

## CAN与配置

26_sentry协议：接收0x329、发送0x330、标准8字节；Pin/Pout/能量大端有符号百分之一，能量单位百分比。发送目标功率前两字节，byte2固定0，其他字节0。原参考cappower_enable参数没有实际写入线上报文，因此不声称支持远程使能。

默认`User/xrobot.yaml`仍仅板级，未启动底盘/电机/超电/裁判。`config/templates/chassis.yaml`包含功率参数、CAN1超电和USART1裁判（沿用原车接线），仅由编译回归工具合成未启用组合。`Param::power.enabled`默认false，模板显式true；请勿把默认固件编译成功当成实际底盘运行证明。

## 验证入口及边界

- `python3 tests/power/run_tests.py`：10000组正反向分配、能量/离线分支、独立时间戳、非法输入、RLS首拍公式/2000样本有界性/同帧冻结、负功、不可达预算、真实超电回调复制与协议编码，ASan/UBSan。
- `python3 tests/chassis/run_tests.py`：原轮系及STOP等回归，新增开启功率的真实Chassis/CMD/RMMotor任务组合、RAW功率约束、超电和电机帧、反向电机INT16_MIN反馈电流。
- 公共控制算法回归包含外部限幅积分跟踪；Debug/Release检查构造、组合配置及默认ELF隔离。
- VS Code新增“测试底盘功率控制（主机）”。编译/烧录入口和默认配置不变。

实际功率拟合误差、超电状态码、裁判接线/反馈频率、2ms截止时间和负载下功率合规尚未硬件验证。模型预算约束不是对真实电气功率的保证。
