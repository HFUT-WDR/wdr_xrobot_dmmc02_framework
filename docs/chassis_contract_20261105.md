# 底盘命令单位和零目标约定

本次按已确认约定更新命令契约及此前审查项，不烧录、不运行电机。

## 最终行为

- `CMD::ChassisCMD.x/y`统一为m/s，`z`为rad/s；X前、Y左、Z逆时针，坐标系仍由frame明确表达。
- I6x、DR16、裁判图传键鼠在输入端映射物理速度。默认平移量程2.64m/s、旋转量程12rad/s、平移死区10/660；配置在各输入模块的YAML参数中。I6x旋钮仍沿用原车单向旋转映射。
- HostData三浮点协议布局不变，PC物理目标直接透传，移除底盘内原PC的0.04m/s固定死区。
- 所有来源的精确零平移目标当拍清对应轴平移滤波历史，保留轮速闭环制动；按后续确认，跟随模式斜坡暂留，最终给定仍可经斜坡减速，不宣称所有模式当拍给定归零。非零目标继续使用原平移滤波；普通切源共用历史。
- RELAX、离线、反馈失效及STOP沿用清控制历史和零电流。普通零目标与无力的含义不同，不增加valid或停轴字段。

遥控松杆会比旧版平滑衰减更直接地制动。这是本次明确接受的行为变化；实际制动手感和电流峰值需要后续实车验证，不能从主机测试推断。

## 审查项落地

Chassis不再查询命令来源来解释单位。常驻ASyncSubscriber在标称2ms控制线程的周期入口读取命令、姿态和云台输入，正常计算和发送共用本拍快照。ASync只捕获等待后的第一帧；复制消息后重新等待，缓冲占用期间的后续发布仍可能被忽略，普通速度目标依赖持续发布，不要求逐帧执行。不再保留旧版同Topic原子STOP/非法数据回调或命令、姿态停更门控。遥控离线、任一轮反馈超时、云台stop_chassis及算法数值故障按拍使整底盘无力；条件恢复后按当前请求模式自动继续。发送阶段不再次消费输入或重选模式，拍内到达的模式请求下一拍处理，不把标称周期当作已实测的响应截止时间。

I6x组合变化先发全部退出事件，再发进入事件，避免旧EXIT覆盖新ENTER。模式绑定使用保持事件（`ChordHold`），每个有效帧按当前组合重发，链路恢复后自动回到该模式（2026-11-07按26_sentry修订）。

电机逻辑轮序由注入对象确定，不与CAN ID排序绑定。仍要求同总线、M3508和唯一完整命令组（201..204或205..208）。Chassis参数有默认值，线程栈和优先级可配置；默认仍为4096字节、MEDIUM和2ms。

默认板级配置未增加外接实例。可选配置、外设模板及版本锁同步更新；VS Code产物路径、构建预设和烧录参数没有改变。

## 原始验证记录（2026-11-05）

以下是早期版本的验收记录，其中STOP原子标记、姿态超时和模块数量等描述不代表当前实现。2026-11-07的保持事件、故障恢复及云台停止电平许可由当前主机测试覆盖；本次整理的运行结果另行记录。

- 底盘主机测试：1000组冻结运动学对照；非零滤波历史、精确零清历史、0.01m/s小目标、转动轮子的零目标闭环制动与RELAX零电流；逻辑轮序置换和CAN实际槽位；缺失/过期yaw、电机过期、遥控失联、RAW保护；异步槽已占用时后到STOP仍阻止输出。ASan/UBSan通过。
- I6x主机测试：1568组冻结解码对照；死区与可配置物理量程；真实EventBinder下组合退出/进入顺序；CMD路由、HostData低速/零目标、PC分通道过期及STOP。ASan/UBSan通过。
- IMU回归：板载5000组、DM8100组冻结源对照；CAN/RS485事务、组帧、安装矩阵、队列和异步缓冲生命周期通过。
- 板级RAM生命周期和裁判协议布局检查通过。
- 默认板级Debug/Release构建、13个模块构造及6个完整配置生成/编译检查通过；未启用模块未链接进默认ELF。
- 可选I6x、RS485 IMU、CAN IMU、旧版IMU、底盘五个配置的独立Debug固件完整链接通过。
- `xrobot setup --frozen --offline`通过，17个模块、6个配置；主工程继续选择`User/xrobot.yaml`。

这些结果不证明真实RTOS截止时间、栈余量、CAN方向、实车制动或机构闭环。未烧录；底盘仍缺真实云台反馈生产者，缺少反馈时保持无力。冻结算法、PID数值、硬件ID默认值及协议线缆布局未调整。
